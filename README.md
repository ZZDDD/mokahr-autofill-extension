# Mokahr Autofill Extension

> [!WARNING]
> **自动填写可能不准确，请务必在提交前逐项检查！**
>
> 请重点核对姓名、联系方式、证件信息、学校、公司、经历顺序和日期。页面改版、公司自定义字段或下拉选项差异都可能导致漏填、错填或未匹配。本扩展不会自动提交申请，最终内容和提交操作由使用者本人确认并负责。

## 🚀 快速开始：5 分钟完成安装

> [!TIP]
> **第一次使用，从这里开始：**
>
> **[⬇️ 点击直接下载仓库 ZIP](https://github.com/ZZDDD/mokahr-autofill-extension/archive/refs/heads/main.zip)**

### 1. 安装扩展

推荐直接下载整个仓库，步骤最少：

1. 点击仓库首页绿色的 `Code` 按钮，再点 `Download ZIP`。也可以[直接下载仓库 ZIP](https://github.com/ZZDDD/mokahr-autofill-extension/archive/refs/heads/main.zip)。
2. 解压 ZIP。
3. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
4. 开启“开发者模式”，点击“加载已解压的扩展程序”。
5. 选择解压得到的 `mokahr-autofill-extension-main` 文件夹。

看到 `Mokahr Resume Autofill` 就安装成功了。建议把它固定到浏览器工具栏。

备选：只想下载扩展运行文件时，可打开 [Releases](https://github.com/ZZDDD/mokahr-autofill-extension/releases/latest)，滚动到页面底部，在 `Assets` 中下载 `mokahr-autofill-chrome-edge-v0.7.0.zip`。解压后用相同方式加载。详细说明和常见问题见 [INSTALL.md](INSTALL.md)。

扩展是原生 Manifest V3 项目，日常使用不需要构建，也不需要安装 npm 依赖。

### 2. 建立简历资料

1. 点击扩展图标，再点击“管理资料与附件”。
2. 在可视化管理页逐项添加信息和经历。
3. 可选：选择附件简历。附件保存在当前浏览器配置文件的扩展本地存储中。
4. 点击“保存简历”。页面会显示内部存储位置、版本、时间和操作回执。

已有兼容 JSON 时，可点击“导入 JSON”。回执会显示导入文件名；浏览器安全机制不允许网页读取源文件夹的完整路径。

### 3. 填写申请页

1. 打开 `*.jobs.feishu.cn` 或 `*.mokahr.com` 的职位申请页。
2. 等页面表单出现后点击扩展图标。
3. 点击“填充当前页面”。
4. 检查已填内容、未匹配项和招聘页必填项。
5. 确认无误后，由你手动提交。

如果刚刚重新加载或升级扩展，请刷新已经打开的申请页，使内容脚本版本保持一致。

---

一个本地运行的 Chrome / Edge 扩展，用同一份结构化简历填充不同公司的 Mokahr 与飞书招聘申请页。扩展只负责填写，不会自动提交申请。

> 当前版本：`0.7.0`。项目仍处于早期阶段，招聘网站改版或租户自定义字段可能导致部分内容无法匹配，提交前必须人工检查。

## ✨ 功能

- 可视化管理基本信息、教育、工作、实习、项目、作品、获奖、语言和社交账号
- 自动创建并按顺序填写多条重复经历，避免后续条目覆盖第一条
- 支持 Mokahr / 飞书常见输入框、下拉框、年月选择器与租户自定义字段
- 从正在填写的申请页反向更新本地简历
- 管理页实时接收反向更新，避免旧表单再次保存时覆盖新资料
- 导入、导出兼容 JSON，并清楚显示文件名、保存路径和最近操作状态
- 在浏览器本地存储附件简历；JSON 导出不包含附件
- 附带 Codex Skill，可从自然语言或 PDF 生成并校验首次使用所需的 JSON

## 🔄 从申请页反向更新

在申请页手动补充或修改资料后，点击扩展里的“从当前页面更新资料”。扩展会把页面中明确读取到的内容写入 `chrome.storage.local / profile`：

- 已打开的管理页会立即加载最新资料和状态，无需刷新页面。
- 若管理页当时存在未保存编辑，这些旧编辑会被反向更新替换，并显示明确提示，从而避免下一次“保存简历”把新资料覆盖回去。
- 页面未出现或保持空白的经历不会随意清空本地数据；明确勾选“没有工作经历”时才会清空工作经历。

反向更新后仍应在管理页复核各条经历，尤其是公司自定义的下拉选项和日期字段。

## JSON 管理

- “导入 JSON”会校验顶层对象及各经历数组，并将资料写入扩展本地存储。
- “导出 JSON”会打开浏览器“另存为”窗口；完成后显示浏览器返回的实际保存路径。
- JSON 只保存结构化资料，不包含附件文件。
- 管理页中的“JSON 文件路径”只是便于用户记录自己维护的文件位置，不会自动读取该路径。

可从 [examples/profile.example.json](examples/profile.example.json) 查看脱敏示例。日常维护建议使用可视化管理页，不必直接编辑 JSON。

## 🤖 从自然语言或 PDF 生成 JSON

仓库内置 [mokahr-profile-json Skill](skills/mokahr-profile-json/SKILL.md)，供 Codex 等支持 `SKILL.md` 的 agent 将自然语言或 PDF 简历转换为兼容 JSON。Skill 会要求 agent 保留经历顺序、不猜测缺失信息、规范日期并在交付前运行本地校验。

安装到 Codex 的个人 Skill 目录：

```bash
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
cp -R skills/mokahr-profile-json "${CODEX_HOME:-$HOME/.codex}/skills/"
```

重新启动 Codex 后，可以这样使用：

```text
使用 $mokahr-profile-json，把这份 PDF 简历转换为本扩展可导入的 mokahr-profile.json。
```

或直接提供自然语言：

```text
使用 $mokahr-profile-json，根据下面的教育、实习和项目信息生成 JSON；缺失字段留空，不要猜测。
```

生成后，在扩展管理页点击“导入 JSON”。简历和生成的 JSON 都包含敏感信息，不应提交到 Git。

## 隐私与权限

扩展没有服务端，也没有分析、遥测或第三方上传代码。资料保存在当前浏览器配置文件的 `chrome.storage.local` 中，该存储与普通网页隔离，但不是密码加密保险箱。

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存结构化资料、状态和附件 |
| `unlimitedStorage` | 避免较大附件超过默认扩展存储配额 |
| `downloads` | 导出 JSON 并记录浏览器返回的保存路径 |
| 招聘站点访问权限 | 在 Mokahr / 飞书申请页读取和填写表单 |

请勿在公用电脑保存简历。移除扩展或清除扩展数据前，先导出需要保留的 JSON。仓库的 `.gitignore` 已覆盖常见简历文件和页面快照命名，但提交前仍应自行检查暂存内容。

## 开发与验证

建议使用 Node.js 22.13+（仅开发和测试需要）：

```bash
npm ci
npm run check
```

`npm run check` 会执行 JavaScript 语法检查、示例 JSON 校验和自动化测试。测试覆盖反向更新实时同步、重复条目创建、React 延迟覆盖修复、日期规范化、页面反向读取及关键 UI 状态。

修改源码后，在扩展管理页面点击“重新加载”，并刷新目标申请页。生成可分发 ZIP：

```bash
npm run package
```

产物写入 `dist/`，打包脚本采用运行文件白名单并同时生成 SHA-256 校验文件，不会包含测试、Git 历史、Skill、本地简历或页面快照。

## 已知限制

- 招聘网站 DOM、组件行为或字段路径变化后，匹配逻辑可能需要更新。
- 公司自定义字段、下拉选项和地区名称不一致时，部分项目会显示为“未匹配”。
- 扩展只支持清单中声明的 Mokahr / 飞书域名，不处理其他 ATS。
- 自动填充不能替代人工核对，尤其是证件、联系方式、日期和经历顺序。
- PDF 转 JSON 的质量取决于 PDF 文本层或 OCR 质量，生成结果必须复核。
